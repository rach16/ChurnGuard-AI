# 0002 — Derive the golden evaluation set from data, not an LLM

**Status:** Accepted · **Date:** 2026-08-30 · **Commit:** `060695c`

## Context

The golden evaluation set was generated by prompting an LLM over the data folder.
All 54 of its questions referenced companies — "Armadillo Shell Systems", "Cheetah
Speed Data" — that exist in **no data file**, before or after the dataset rebuild.
0 of 54 were grounded.

RAGAS was therefore scoring retrieval against answers that could never be
retrieved, and reporting a number. That number became the project's headline
claim.

## Decision

Generate questions and ground truths by **computing them from the data**.
`scripts/generate_golden_dataset.py` reads `customers.csv` and its fact tables and
emits 65 questions across five query types, each with an answer derived
arithmetically from the source.

## Consequences

Ground truths are verifiable by construction and cannot hallucinate. The set
regenerates whenever the data changes, so it cannot silently rot. `expected_context`
now carries real `customer_id`s, making retrieval precision directly scoreable.
Four validator checks fail CI if the set ever stops being grounded.

The limitation, discovered afterwards: roughly a third of the generated questions
are aggregates — "which segment has the highest churn rate" — which **retrieval
structurally cannot answer**, because the answer is a computation over the whole
dataset rather than a fact in any document. Including them depresses measured
recall for a reason that has nothing to do with retrieval quality. They should be
routed to SQL against the warehouse instead. Tracked, not yet done.

## Alternatives considered

**Regenerate with a better LLM prompt.** Rejected: the failure was not prompt
quality but the absence of any mechanism forcing answers to be true.

**Hand-write the questions.** Rejected: does not scale and cannot be regenerated
when the data changes.
